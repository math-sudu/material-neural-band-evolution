# Observation-directed virtual work for cohesion identification

Numerical reproduction code for **Observation-directed virtual work for cohesion
identification with mixed physics-informed neural networks**, by Pengcheng Zhu
and Tielin Chen.

The comparison identifies a positive cohesion-evolution law in a finite inelastic
band within a known elastic host. Two mixed-field neural identifications start
from the same checkpoint. One adds a virtual-work penalty generated by the
surface observation operator and a fixed reference stiffness. Each exported
material is then used to solve the prescribed history without the field networks.

## Inputs and installation

Use Python 3.13 and install `requirements.txt`. For GPU runs, install the PyTorch
2.8.0 build suitable for your CUDA environment, then use `--device cuda` below.
The paper runs used PyTorch 2.8.0 with CUDA 12.6. CPU execution is also supported.
Gmsh on Linux requires the system OpenGL/GLU runtime.

```text
python -m pip install -r requirements.txt
python reproduce.py check
```

`inputs/case.json` contains the registered m-1-1 specimen geometry, 401 curved
surface locations, local observation coordinates, validity masks, and twelve
rising-load values from the authors' Material experimental series. They are
the irreducible experimental inputs to the numerical case. The displacement
targets are generated by the prescribed material; no measured displacements
are needed or included. Three numerical unloading/reloading states are appended
by the solver. Units are N, mm and MPa.

## Reproduce the comparison

```text
python reproduce.py all --device cuda
```

The stages can also be run separately in this order:

```text
python reproduce.py common-start --device cuda
python reproduce.py control --device cuda
python reproduce.py virtual-work --device cuda
python reproduce.py evaluate
```

The shared start uses 700 Adam steps followed by at most 250 L-BFGS iterations.
Adam uses learning rates 0.002 for the field networks and 0.0004 for the material.
Each continuation uses at most 350 L-BFGS iterations; the additional virtual-work
weight is 0 or 100. Both continuations use exactly the same starting checkpoint.
The code regenerates synthetic observations, checkpoints, material exports,
replay fields and all numerical figure inputs under `results/`. These generated
files are excluded from the repository.

`results/paper_evidence/comparison_summary.csv` contains the table-level
metrics. `cohesion_comparison.csv`, `response_metrics.csv`, `window_histories.csv`
and `response_fields.npz` supply the full material curves, displacement
histories, finite-window offsets and spatial fields. The extraction script
reintegrates each material history and reconciles the saved losses and response
metrics. It performs no further training.

The reported comparison reduces maximum sampled cohesion error from 0.5395 to
0.1266 MPa and mean spatial-holdout deformation RMSE from 0.11581 to 0.04429
micrometres. The mean is over fourteen nonreference states and 93 holdout points,
after a rigid fit over the union of 97 training and 93 holdout points. This is
a noise-free same-mesh numerical comparison under one prescribed history.
Optimization results can vary with numerical-library and device behavior.

## Source organization

- `run_mixed_pinn.py`: mixed neural fields, equilibrium projection, training and replay.
- `band_material.py`: nonlocal pressure-dependent band plasticity and neural cohesion.
- `band_forward.py` and `condensed_band.py`: mesh, host condensation and mechanical solution.
- `diagnose_synthetic_material.py`: known-material history and common cohesion samples.
- `prepare_paper_inputs.py` and `analyze_paper_evidence.py`: input and numerical reconciliation.

The solver modules are copied from the research implementation. This package
replaces only the experimental-file loader with the published case input and
reduces the observation-preparation module to the rigid-motion matrix actually
used by this calculation. The input-summary writer omits the unrelated full
experimental-series inventory. Numerical material, field, training and replay
operations are unchanged. Additional constitutive helper modules are included
because they are imported by the shared solver; the paper commands use the
elastic-host, band-only branch.
